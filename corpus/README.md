# Fastvid corpus

The canonical corpus has two reproducible source paths:

1. Twenty AI-generated 1080p originals are generated once and distributed as
   one immutable tarball.
2. The 100 non-AI source masters used to construct the 4K corpus are downloaded
   or deterministically generated by the pinned corpus script. They are not
   bundled into a tarball.

All heavy files live under the gitignored `corpus/sources/` directory.
Normalized evaluator inputs live under the gitignored `artifacts/` directory.

## Frozen AI sources

The AI images must never be regenerated during corpus setup. Their full prompts
are stored in `ai-prompts.json`, their hashes in
`ai-source-checksums.sha256`, and their archive is:

```text
corpus/fastvid-corpus-v1-ai-sources.tar.gz
```

Create the deterministic archive after generating the images once:

```sh
python scripts/corpus.py archive-ai
```

On another machine, extract it into `corpus/sources/`:

```sh
tar -xzf corpus/fastvid-corpus-v1-ai-sources.tar.gz -C corpus/sources
(cd corpus/sources && sha256sum --check ../ai-source-checksums.sha256)
```

The archive contains `ai/`, `ai-prompts.json`, and
`ai-source-checksums.sha256`. The archive itself is gitignored so it can be
hosted or transferred independently. Its expected hash is committed in
`ai-archive.sha256`.

## Fetched source masters

`master-sources-v1.json` freezes exact URLs, source groups, licenses, and
selection metadata. `master-source-checksums-v1.sha256` freezes the expected
downloaded bytes. Fetch and verify everything with:

```sh
python scripts/corpus.py fetch-masters
```

The command is resumable, downloads into `corpus/sources/v1/`, and fails if a
remote file no longer matches the committed SHA-256. It does not regenerate AI
images and does not require the AI archive.

The 100 source masters are:

- 50 CC0 camera RAW files from 50 distinct camera models;
- 24 CC0 4K OpenEXR HDRIs from 24 distinct Poly Haven assets;
- 10 CC BY 4.0 Netflix Open Content high-bit sources, capped at two frames
  from each of Chimera, Meridian, Sparks, El Fuente Boat, and El Fuente Food
  Market;
- 4 lossless Xiph frames, capped at two each from Sintel and Tears of Steel;
- 8 open-source game screenshots from 8 distinct titles;
- 4 deterministic 3840×2160 little-endian RGB48 raw stress patterns.

The four El Fuente entries are fetched as exact one-frame byte ranges from the
original 10-bit 4:2:0 Y4M files. This avoids downloading roughly 24 GB of
sequence data while preserving raw frame samples.

The game set is the deliberate low-bit exception. It uses one title each from
Veloren, 0 A.D., Minetest, SuperTuxKart, The Battle for Wesnoth, Endless Sky,
Freeciv, and Xonotic. Seven sources are lossless PNG; Xonotic is a native 4K
JPEG because a suitable freely licensed lossless capture was not available.
The manifest records native dimensions, format, license, page, and revision.

## Maintainer workflow

`discover-masters` is not part of normal setup. It queries the source APIs to
propose and freeze a new catalog revision:

```sh
python scripts/corpus.py discover-masters
python scripts/corpus.py fetch-masters --refresh-checksums
```

Refreshing checksums is an explicit maintainer action because it changes corpus
identity. Review all source, license, diversity, and visual changes before
committing the new catalog and hashes.

Requires Python 3.11+, NumPy, and rawpy 0.25.1.

See `SOURCE_POLICY.md` for source-quality and diversity rules.
