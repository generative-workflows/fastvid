# 0001 — FFV1

Source: M. Niedermayer, D. Rice, J. Martinez, “FFV1 Video Coding Format
Versions 0, 1, and 3,” IETF RFC 9043, 2021.

- Specification: https://www.rfc-editor.org/rfc/rfc9043.html
- Terms: RFC code components are provided under the Simplified BSD License;
  this project uses the document as design literature and copies no code.

## Findings

FFV1 demonstrates that an intra-frame format can serve preservation and
intermediate workflows. Its independently described slices provide a useful
model for corruption containment, random access, and multithreaded decoding.
It also provides precedent for supporting planar Y/Cb/Cr and Golomb-Rice
entropy coding.

## Fastvid implications

1. Make tiles independently decodable and include a directory with explicit
   byte ranges.
2. Keep spatial prediction causal within a tile so scheduling order does not
   affect output.
3. Treat entropy coding as a replaceable experimental component.
4. Do not copy FFV1 syntax; Fastvid's version-zero container is intentionally
   small and unstable.
